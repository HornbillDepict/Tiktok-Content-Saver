## The longer version

Removing the extracted folder eliminates everything that the archive placed there.

Using the program means unpacking the zip and running the file named `setup`, while a later build is another archive downloaded and started the same way.

## What changed

- Extract the zip file and run `setup` to start the program
- One folder, packed as a zip, is the download.
  - A later build arrives as a separate archive.
- Failed starts belong in an issue that states the Windows version and the step that stopped.

## Troubleshooting

<details><summary>`setup` left the folder on its own</summary>

It belongs with the other files. Either return it there or extract the archive again.
</details>

<details><summary>SmartScreen returned for the new zip</summary>

A new file counts, to Windows, as a new download.
</details>

<details><summary>Corporate laptop blocks the folder</summary>

IT needs to allow the folder. The file is a plain unsigned Windows build inside a plain zip.
</details>

<details><summary>Added files vanished under the new extract</summary>

Those added files survive if you copy them out before the new archive lands on the folder.
</details>

<details><summary>Initial start showed a signature warning</summary>

No signature is attached to the file. More info and then Run anyway carries the first launch through.
</details>

<details><summary>The saved copy still carries a block</summary>

Properties is where Unblock lives. Tick it, and start `setup` once more.
</details>
